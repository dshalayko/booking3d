# Бронирование 3D-принтеров

Система для коворкинга с двумя Bambu Lab P2S Combo. Доступ бесплатный, филамент
общий, ночные печати разрешены.

Главный интерфейс — **iPad, постоянно висящий на стене**: видно, кто печатает,
сколько осталось и кто следующий в очереди. Уведомления приходят в Telegram.

- [PLAN.md](PLAN.md) — правила системы, модель данных, что и почему сделано
- [DEPLOY.md](DEPLOY.md) — развёртывание на VPS

## Быстрый старт

Нужны Docker и Python 3.12+.

```bash
./run.sh
```

Скрипт создаст `.env` со сгенерированными секретами, виртуальное окружение,
поднимет Postgres, накатит миграции, засеет два принтера и запустит приложение
на `http://127.0.0.1:8000/`.

Чтобы заработал бот, впиши `TG_BOT_TOKEN` от [@BotFather](https://t.me/BotFather)
в `.env`. Без токена работает всё, кроме уведомлений.

## Команды

```bash
./run.sh help
```

| Команда | Что делает |
|---|---|
| `./run.sh` | поднять всё и запустить приложение |
| `./run.sh test` | 223 теста на отдельной базе `booking_test` |
| `./run.sh check` | линтер и тесты |
| `./run.sh urls` | ссылки на киоск, регистрацию киоска и админку |
| `./run.sh admin <tg_id>` | выдать права админа |
| `./run.sh demo` | создать двух тестовых людей с PIN 1111 и 2222 |
| `./run.sh fastforward` | сдвинуть сроки в прошлое, чтобы проверить напоминания |
| `./run.sh reset` | очистить состояние |
| `./run.sh psql` | консоль базы |
| `./run.sh stop` | остановить приложение и базу |

Принтеры заводятся отдельно — их парк объявлен в `PRINTER_NAMES` (`.env`):

```bash
python -m app.cli seed_printers                     # создать недостающие
python -m app.cli printers                          # показать с их id
python -m app.cli rename_printer "P2S #1" "Bambu X1"  # поменялась машина
```

`seed_printers` только добавляет: правка `PRINTER_NAMES` не переименует уже
созданный принтер и не удалит лишний. Имя лежит в строке таблицы `printers`, на
которую ссылаются печати и очередь, поэтому переименование — отдельная явная
команда, а увезённый принтер выводится в обслуживание из админки, чтобы история
осталась целой.

Если в имени есть `#`, значение в `.env` **обязано** быть в кавычках:
`PRINTER_NAMES="P2S #1,P2S #2"`. Без них dotenv обрежет строку по решётке, и
вместо двух принтеров создастся один с именем `P2S`.

## Как проверить, что всё работает

**1. Зарегистрируй браузер как киоск.** Без этого форма ввода PIN не появится:
она доступна только на устройстве-киоске, иначе четыре цифры перебирались бы из
интернета за минуты.

```bash
./run.sh urls
```

Открой ссылку «регистрация киоска» — ставится cookie на 10 лет.

**2. Заведи себя.** Напиши боту `/start` — он спросит корпоративный логин вида
`n_username`; ответь им, и бот выдаст PIN. Под этим логином тебя будет видно на
планшете и в журнале. Права админа:

```bash
./run.sh admin <твой telegram chat id>
```

**3. Заведи тестовых людей.** Один аккаунт не может одновременно печатать и
стоять в очереди, поэтому для проверки очереди нужны ещё двое:

```bash
./run.sh demo
```

**4. Прокликай цикл** на `http://127.0.0.1:8000/`:

1. «Занять» → PIN `1111` → «4 ч». Плитка краснеет.
2. Занять второй принтер PIN `2222`. Большая кнопка меняется на «Встать в очередь».
3. «Встать в очередь» своим PIN — появляешься в строке очереди.
4. На первом принтере «Освободить» → PIN `1111`. Плитка синеет
   («Зарезервирован до HH:MM»), а тебе приходит уведомление в Telegram.
5. Боту `/status` и `/my` — должно совпадать с экраном.
6. С телефона открой тот же адрес — статусы видно без входа, но занять
   принтер оттуда нельзя: это делается только с планшета у принтеров.

**5. Проверь напоминания, не ожидая часами.** Планировщик сверяет состояние раз
в минуту, а занять принтер меньше чем на 15 минут нельзя:

```bash
./run.sh fastforward
```

В течение минуты в логах появится `сверка: … завершено 1`, принтер станет жёлтым
«Заберите деталь», владельцу и первому в очереди уйдут сообщения.

**6. Админка** — `http://127.0.0.1:8000/admin/login`, секрет печатает
`./run.sh urls`. Вывести принтер в обслуживание, снять чужую печать с причиной,
убрать человека из очереди, сбросить PIN, журнал событий.

На проде админка из интернета недоступна: Caddy отдаёт на `/admin*` 404, заходить
нужно через SSH-туннель (см. [DEPLOY.md](DEPLOY.md)).

## Устройство

```
app/
├── main.py          FastAPI, запуск бота и планировщика
├── models.py        4 таблицы: users, printers, sessions, queue
├── services/        домен: без HTTP и без Telegram
│   ├── printers.py  занять, освободить, сломать
│   ├── queue.py     очередь и предложения
│   ├── reminders.py сверка состояния с часами
│   ├── timeutil.py  ночная пауза
│   ├── board.py     состояние парка для экрана и бота
│   ├── activity.py  журнал событий из таблиц
│   └── auth.py      токены, PIN, ограничение попыток
├── api/             экраны киоска, вход, админка
├── bot/             aiogram: команды и уведомления
├── texts/           все тексты интерфейса, по файлу на язык
└── templates/       Jinja2, без внешних CDN
```

Ни одной формулировки в коде нет: сообщения бота, надписи на киоске, тексты
отказов и строки журнала лежат в `app/texts/ru.py` и `app/texts/en.py`, а код
берёт их по имени. Язык переключается переменной `UI_LANG` (`ru` или `en`) и
применяется после рестарта. Новый язык — копия `ru.py` с переведёнными
значениями плюс строка в `LANGUAGES`; что набор имён и плейсхолдеров совпал,
проверяет `tests/test_texts.py`.

Тесты проверяют формулировки дословно, поэтому идут всегда на русском —
`conftest.py` фиксирует `UI_LANG` независимо от `.env`.

Домен не знает ни про HTTP, ни про Telegram: сервисы возвращают результаты
(`OccupyResult`, `Offer`), а рассылкой занимается слой выше. Поэтому логика
тестируется без моков — на настоящем Postgres и без единого мока Telegram.

## Правила, ради которых всё это

Полный список — в [PLAN.md](PLAN.md), здесь пять самых важных:

1. **Очередь общая на оба принтера.** Принтеры идентичны; две отдельные очереди
   дали бы «свободен #2, а первый в очереди ждёт #1».
2. **Предложение получает только первый**, а не рассылка всем — иначе очередь
   превращается в гонку «кто быстрее добежит».
3. **Ночью окно подтверждения не тикает** (23:00–08:00). Принтер, освободившийся
   в 03:40, ждёт человека до утра, иначе ночные печати молча опустошают очередь.
4. **Таймер не освобождает принтер.** По истечении срока принтер уходит в
   «готово, деталь на столе», а не в «свободен»: оценка длительности всегда врёт,
   и освобождение вслепую приведёт к двум людям, печатающим на один стол.
5. **Освободить принтер может любой**, не только владелец печати. Стол пустой —
   значит принтер свободен, и парк не должен простаивать из-за того, что владелец
   уехал домой. Кто освободил, пишется в журнал.

## Если что-то не так

**`Conflict: terminated by other getUpdates`** — с одним токеном может работать
только один процесс polling. Убей лишний: `./run.sh stop`. Для разработки заведи
отдельного тестового бота.

**Форма PIN не появляется** — браузер не зарегистрирован как киоск, см. шаг 1.

**Напоминания не приходят** — в логах должна быть строка `сверка: …`. Если её
нет, планировщик не стартовал. Если есть, а сообщений нет — рядом будет
`не удалось отправить сообщение в <chat_id>`.

**Ночная пауза срабатывает не в те часы** — проверь `TZ` в `.env`. По нему
считаются границы ночи.
