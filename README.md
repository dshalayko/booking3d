# Бронирование оборудования и переговорных

Система для коворкинга: 3D-принтеры (Bambu Lab P2S Combo), гравировщики,
переговорные.
Доступ бесплатный, филамент общий, ночные печати разрешены.

Главный интерфейс — **iPad, постоянно висящий на стене**: видно, кто что занял,
сколько осталось и какие часы доступны для бронирования. Уведомления приходят в Telegram.
Оттуда же, из **Telegram Mini App**, можно забронировать машину на конкретный
час — расписание парка открывается на две недели вперёд.

Помещений может быть сколько угодно: мастерская с принтерами, вторая мастерская
в другом корпусе, переговорная. У каждого помещения свои часы работы, но лимит
пользователя общий: одна активная работа или одна бронь во всей системе.

Внутри помещения у каждого типа оборудования своя секция. Переговорную
бронируют так же, как принтер, — она и есть единица брони своего помещения.

**У каждого помещения свой постоянный адрес** `/room/<id>`: его вбивают в
планшет, по нему дают ссылку, из админки на него ведёт кнопка «Открыть экран».
Экрана-каталога «все помещения» нет — человек приходит в конкретную комнату.
**Один планшет — одно помещение**: комната выбирается один раз при регистрации
планшета и запоминается в нём самом. Состав помещений и парка правится из
админки, разделы **«Помещения»** и **«Оборудование»**.

- [PLAN.md](PLAN.md) — правила системы, модель данных, что и почему сделано
- [DEVELOPMENT.md](DEVELOPMENT.md) — актуальные инварианты и правила изменений
- [DEPLOY.md](DEPLOY.md) — развёртывание на VPS

## Быстрый старт

Нужны Docker и Python 3.12+.

```bash
./run.sh
```

Скрипт создаст `.env` со сгенерированными секретами, виртуальное окружение,
поднимет Postgres, накатит миграции, засеет принтеры из `PRINTER_NAMES` и
запустит приложение
на `http://127.0.0.1:8000/`.

Чтобы заработал бот, впиши `TG_BOT_TOKEN` от [@BotFather](https://t.me/BotFather)
в `.env`. Без токена работает всё, кроме уведомлений.

## Команды

```bash
./run.sh help
```

| Команда | Что делает |
|---|---|
| `./run.sh` | поднять всё и запустить приложение |
| `./run.sh test` | полный набор тестов на отдельной базе `booking_test` |
| `./run.sh check` | линтер и тесты |
| `./run.sh urls` | ссылки на киоск, регистрацию планшета и админку |
| `./run.sh admin <tg_id>` | выдать права админа |
| `./run.sh demo` | создать тестовых людей, PIN печатаются |
| `./run.sh fastforward` | сдвинуть сроки в прошлое, чтобы проверить напоминания |
| `./run.sh reset` | очистить работы и брони, удалить тестовых людей |
| `./run.sh psql` | консоль базы |
| `./run.sh stop` | остановить приложение и базу |

### Помещения

Обычное место для этого — админка, раздел «Помещения»: там комнату заводят (имя
и тип), переименовывают и удаляют. Те же действия есть в командной строке — на
случай, когда админка недоступна: свежая база, разбор на месте по SSH.

```bash
python -m app.cli rooms                                  # показать с id и типом
python -m app.cli add_room "Переговорная «Дуб»" --kind meeting
python -m app.cli add_room "Мастерская на первом"        # по умолчанию workshop
```

Типа два, и разница между ними одна: что в помещении стоит. В мастерской —
принтеры и гравировщики, в переговорной — сама переговорная: её единица брони
создаётся вместе с комнатой и переименовывается вместе с ней. Принтер в
переговорную завести нельзя, и наоборот.

Тип помещения после создания не меняется — на комнату уже ссылаются работы и
брони.

Удалить мастерскую можно, когда в ней не осталось оборудования; переговорная
удаляется одной кнопкой вместе со своей единицей брони — она не отдельный
объект, а сама комната. Отказ приходит только тогда, когда за помещением уже
есть история: работы, приглашения или брони. Закрывшуюся комнату с историей
лучше оставить как есть, а оборудование вывести в обслуживание — тогда занять
ничего нельзя, а журнал остаётся целым.

Заведя помещение, задай ему часы работы (раздел «Часы работы») и повесь на него
планшет: у каждой комнаты свой постоянный адрес `/room/<id>`, он показан рядом с
ней в админке — там же кнопка «Открыть экран». Экрана «все помещения» в системе
нет намеренно: человек приходит в конкретную комнату, а не выбирает из каталога.

### Парк оборудования

Админка, раздел «Оборудование»: машину заводят (помещение, имя и тип),
переименовывают и удаляют.

```bash
python -m app.cli machines                              # показать с id, помещением и типом
python -m app.cli add_machine "Гравёр #1" --kind engraver --room "Мастерская"
python -m app.cli rename_machine "P2S #1" "Bambu X1"    # поменялась машина
python -m app.cli remove_machine "Гравёр #1"            # только без истории
python -m app.cli seed_printers                          # принтеры из PRINTER_NAMES
```

Тип и помещение задаются при создании и потом не меняются: на строку уже
ссылается журнал, и «принтер, который вдруг стал гравировщиком» превратил бы
прошлые печати в гравировки, а переезд между комнатами переписал бы прошлое —
работы и брони помнят, где всё происходило. Удалить можно только машину без
единой работы, брони и приглашения — увезённая машина с историей выводится в
обслуживание, тогда журнал остаётся целым. Переименование историю сохраняет:
меняется имя той же строки.

`PRINTER_NAMES` (`.env`) нужна ровно один раз — чтобы на свежей базе появились
принтеры и было что показать на стене; дальше парк живёт в таблице `machines`.
Принтеры заводятся в первое помещение — то самое, которое миграция создаёт на
свежей базе. `seed_printers` только добавляет недостающее по имени, ничего не
удаляет, а гравировщиков и переговорных не касается вовсе.

Если в имени есть `#`, значение в `.env` **обязано** быть в кавычках:
`PRINTER_NAMES="P2S #1,P2S #2"`. Без них dotenv обрежет строку по решётке, и
вместо двух принтеров создастся один с именем `P2S`.

## Как проверить, что всё работает

**1. Зарегистрируй браузер как киоск.** Без этого форма ввода PIN не появится:
она доступна только на устройстве-киоске, иначе четыре цифры перебирались бы из
интернета за минуты.

```bash
./run.sh urls
```

Открой ссылку «регистрация планшета» — она спросит, в каком помещении висит этот
планшет, и после выбора поставит cookie на 10 лет. Дальше главный экран этого
устройства — доска выбранной комнаты и только её.

**2. Заведи себя.** Напиши боту `/start` — он спросит корпоративный логин вида
`n_username`; ответь им, и бот выдаст PIN. Под этим логином тебя будет видно на
планшете и в журнале. Права админа:

```bash
./run.sh admin <твой telegram chat id>
```

**3. Заведи тестовых людей.** Один аккаунт не может одновременно занимать две
машины или держать две брони, поэтому для проверки параллельной работы нужны
ещё люди:

```bash
./run.sh demo
```

**4. Прокликай цикл** на `http://127.0.0.1:8000/`:

1. «Занять» → PIN `1111` → «4 ч». Плитка краснеет.
2. Занять второй принтер PIN `2222`. Прямого действия больше нет, но кнопка
   «Расписание» остаётся доступной.
3. Выбрать в расписании свободный час на завтра и оформить бронь PIN `3333`.
4. На первом принтере «Освободить» → PIN `1111`. Плитка снова становится зелёной.
5. Боту `/status` и `/my` — должно совпадать с экраном.
6. Заведи гравировщик в админке («Оборудование») — в этом же помещении появится
   отдельная секция со своим расписанием.
   Заведи переговорную («Помещения» → тип «Переговорные») — кнопка «Открыть
   экран» рядом с ней ведёт на её доску: одна плитка с именем комнаты, кнопка
   «Занять переговорную» и своё расписание. Пользователь с активной работой на
   принтере не сможет одновременно занять переговорную: лимит общий для всей
   системы. Пока встреч в ней не было, она удаляется тем же разделом одной кнопкой.
7. С телефона открой тот же адрес — статусы видно без входа, но занять
   машину оттуда нельзя: PIN вводится только на планшете в мастерской.
   Действия с телефона живут в Telegram Mini App, см. «Брони на будущее».
8. «Расписание» в секции принтеров → сетка «часы × машины» на две недели.
   Свободный час на завтра → длительность → PIN. На плитке появится
   «бронь с HH:MM», а занять машину дольше, чем до неё, экран уже не предложит.

Если планшет ещё не зарегистрирован как киоск, а прогнать цикл надо уже сейчас —
`KIOSK_OPEN_ACCESS=true` в `.env` снимает привязку к устройству, и занимать
машины можно с любого. PIN при этом проверяется как обычно, но четыре цифры
на публичном адресе перебираются из интернета, так что на проде это режим на
время проверки, а не постоянный. Приложение пишет предупреждение в лог при
каждом старте, пока флаг включён.

**Mini App без Telegram.** Мини-приложение открывается только по https и только
из бота, поэтому локально проверить его иначе нельзя:
`MINIAPP_OPEN_ACCESS=true` в `.env` заменяет подпись Telegram на выбор человека
из списка — открой `http://127.0.0.1:8000/app/` в обычном браузере, ткни в имя и
работай как он: расписание, брони, «мои брони», занять и освободить.

Флаг опаснее предыдущего: там для действия всё ещё нужен PIN, здесь — ничего.
На публичном сервере его включать нельзя, и приложение предупреждает об этом в
лог при каждом старте. Что он **не** отключает: подпись, если она пришла.
Подделанный `initData` отклоняется и с включённым флагом — иначе проверка
перестала бы что-либо значить, а тесты на неё зеленели бы впустую.

**5. Проверь напоминания, не ожидая часами.** Планировщик сверяет состояние раз
в минуту, а занять машину меньше чем на 15 минут нельзя:

```bash
./run.sh fastforward
```

В течение минуты в логах появится `сверка: … завершено 1`, машина станет жёлтой
«Заберите деталь», а владельцу уйдёт сообщение.

**6. Админка** — `http://127.0.0.1:8000/admin/login`, секрет печатает
`./run.sh urls`. Разделы — в меню слева, по файлу на раздел
(`app/admin/sections/`), меню собирается из их списка; как добавить свой —
в [app/admin/\_\_init\_\_.py](app/admin/__init__.py).

Сверху меню — то, за чем заходят, когда что-то пошло не так. «Сводка» —
состояние парка и кнопки, которыми его чинят: вывести машину в обслуживание,
снять чужую работу с причиной. «Брони» — окна на будущее. «Люди» — завести
человека руками (для тестовых учёток и для тех, кто до бота не дошёл), сбросить
PIN, поправить логин с опечаткой, удалить. «Журнал» — что происходило с парком.

Удалить можно что угодно, но не одним нажатием: кнопка ведёт на экран, где
написано, сколько работ, брон и записей очереди уедет вместе с объектом. Без
этого подтверждения удаляется только то, за чем не записано ничего, — случайный
POST мимо экрана историю не сотрёт. Единственный отказ без обхода — на последнем
админе: от его имени панель пишет в журнал каждое действие. Если машина просто
уехала, а история нужна, её выводят в обслуживание, а не удаляют.

Ниже — настройка. «Помещения» — комнаты: завести, переименовать, удалить,
посмотреть их часы и адрес планшета. «Оборудование» — состав парка по
помещениям. «Часы работы» — по форме на помещение: начать бронь можно только в
эти часы, и расписание показывает ровно их.

На проде она доступна из интернета по тому же адресу — администрировать нужно и с
телефона. Единственный фактор входа при этом `ADMIN_SECRET`, поэтому он живёт в
менеджере паролей и нигде больше; как закрыть обратно — в [DEPLOY.md](DEPLOY.md).

## Брони на будущее

Бронь оформляется на конкретную машину и конкретные часы, шаг сетки — час,
горизонт — две недели, одна активная бронь на человека во всей системе.
Новую бронь можно создать после завершения текущей работы или отмены брони.

Начать бронь можно только в рабочие часы того помещения, где стоит машина, и
расписание показывает ровно их и ничего больше. Конец брони часы не ограничивают:
поставленная в 19:00 печать честно идёт всю ночь, а деталь забирают с открытия.
Сами часы правятся в админке, раздел «Часы работы», по форме на комнату — по
умолчанию 08:00–20:00.

- в своё окно машину занимает только тот, кто её забронировал; администратор
  снимает бронь отдельным действием, чтобы изменение осталось в журнале;
- пока окно не началось, машину можно занять «сейчас», но не дольше, чем до его
  начала: кнопки, которые не влезают, просто не показываются;
- не пришёл за 30 минут с начала окна — бронь снимается и время освобождается.
  Отсчёт идёт только со свободной машины: чужая незабранная деталь чужую бронь
  не съедает.

Бронируют двумя способами. С планшета — кнопка «Расписание» на главном экране,
дальше свободный час, длительность и PIN. С телефона — командой `/book` в боте:
она открывает **Telegram Mini App**, то же самое расписание внутри Telegram.
PIN там не нужен и не вводится: кто пришёл, Telegram подписывает сам
([initData](https://core.telegram.org/bots/webapps), проверяется на токене
бота). В приложении доступно всё то же, что на планшете, плюс «мои брони».

Mini App требует https и непустой `TG_BOT_TOKEN`: по http Telegram приложение не
откроет, и бот честно скажет об этом вместо неработающей кнопки. Адрес
приложения берётся из `PUBLIC_BASE_URL`, кнопка в меню бота ставится на старте
сама — в BotFather ничего настраивать не нужно.

## Устройство

```
app/
├── main.py             FastAPI, запуск бота и планировщика
├── models.py           7 таблиц: users, rooms, machines, sessions, queue,
│                       reservations, work_hours
├── services/           домен: без HTTP и без Telegram
│   ├── rooms.py        помещения: состав и правила заведения
│   ├── machines.py     занять, освободить, сломать; состав парка
│   ├── reservations.py брони на будущее и расписание дня
│   ├── schedule.py     сетка календаря и длительности, без базы
│   ├── workhours.py    часы работы помещения: чтение и правка
│   ├── reminders.py    сверка состояния с часами
│   ├── board.py        состояние парка для экрана и бота
│   ├── activity.py     журнал событий из таблиц
│   ├── users.py        логин: формат и переименование
│   ├── telegram.py     подпись Mini App: initData
│   └── auth.py         токены, PIN, ограничение попыток
├── api/
│   ├── screens.py      экраны и действия, общие для планшета и телефона
│   ├── kiosk.py        роуты киоска: действие подписывает PIN
│   ├── miniapp.py      роуты /app: действие подписывает Telegram
│   └── admin.py        админка
├── bot/                aiogram: команды и уведомления
├── texts/              все тексты интерфейса, по файлу на язык
└── templates/          Jinja2, без внешних CDN
```

Экран у планшета и телефона один и тот же: отличий ровно два — префикс адресов и
клавиатура PIN, — и оба сведены в `Client` (`api/screens.py`). Вторая копия
«показать расписание» разошлась бы с первой на первой же правке.

Ни одной формулировки в коде нет: сообщения бота, надписи на киоске, тексты
отказов и строки журнала лежат в `app/texts/ru.py` и `app/texts/en.py`, а код
берёт их по имени. Язык переключается переменной `UI_LANG` (`ru` или `en`) и
применяется после рестарта. Новый язык — копия `ru.py` с переведёнными
значениями плюс строка в `LANGUAGES`; что набор имён и плейсхолдеров совпал,
проверяет `tests/test_texts.py`.

Тесты проверяют формулировки дословно, поэтому идут всегда на русском —
`conftest.py` фиксирует `UI_LANG` независимо от `.env`.

Домен не знает ни про HTTP, ни про Telegram: сервисы возвращают результаты,
а рассылкой занимается слой выше. Поэтому логика
тестируется без моков — на настоящем Postgres и без единого мока Telegram.

## Правила, ради которых всё это

Полный список — в [PLAN.md](PLAN.md), здесь четыре самых важных:

1. **Таймер не освобождает машину.** По истечении срока она уходит в «готово,
   деталь на столе», а не в «свободна»: оценка длительности всегда врёт, и
   освобождение вслепую приведёт к двум людям, работающим на один стол.
2. **Освободить машину может любой**, не только владелец работы. Стол пустой —
   значит машина свободна, и парк не должен простаивать из-за того, что владелец
   уехал домой. Кто освободил, пишется в журнал.
3. **Бронь гарантирует машину в своё окно** и урезает «занять сейчас» до своего
   начала.
4. **Одна активная работа или одна бронь на человека во всей системе.**
   При небольшом парке без этого один человек забирает комнату целиком; а
   считать лимит на весь коворкинг значило бы, что бронь переговорной запрещает
   печать, хотя это разные дела.

## Если что-то не так

**`Conflict: terminated by other getUpdates`** — с одним токеном может работать
только один процесс polling. Убей лишний: `./run.sh stop`. Для разработки заведи
отдельного тестового бота.

**Форма PIN не появляется** — браузер не зарегистрирован как киоск, см. шаг 1.

**Планшет показывает не то помещение** — он зарегистрирован без комнаты
(например, ещё до появления помещений) и потому открывает первое. Открой ссылку
«регистрация планшета» ещё раз и выбери комнату; можно и просто оставить
открытым адрес её доски (`/room/<id>`) — он показан в админке рядом с
помещением, там же кнопка «Открыть экран».

**Напоминания не приходят** — в логах должна быть строка `сверка: …`. Если её
нет, планировщик не стартовал. Если есть, а сообщений нет — рядом будет
`не удалось отправить сообщение в <chat_id>`.

**Ночная пауза срабатывает не в те часы** — проверь `TZ` в `.env`. По нему
считаются границы ночи.
